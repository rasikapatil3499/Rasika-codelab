STL Containers in C++

Implement programs using STL containers to store, organize and process collections of data efficiently.

LLO 18.14 Topics12 ProblemsCode • Understand • Visualize

Aim

To implement C++ programs using STL containers such as vector, list, stack, queue, map and unordered_map for practical data management.

Learning Objectives

After completing this practical, the learner should be able to:

01 — Sequence Containers

Use vector and list to store and traverse collections.

02 — Container Adaptors

Use stack and queue according to LIFO and FIFO behavior.

03 — Associative Containers

Use map and unordered_map for key-value data.

04 — Integration

Select suitable containers for application-oriented data.

Understanding STL Containers

STL containers provide ready-to-use data structures so programmers can focus on application logic.

Vector & List

vector provides a dynamic sequence with indexed access. list supports linked sequence operations.

Real-life: marks and changing task collections.

Stack & Queue

A stack follows LIFO and a queue follows FIFO.

Real-life: undo history and service counters.

Map

A map associates unique keys with values and keeps keys ordered.

Real-life: roll number → student name.

Unordered Map

An unordered_map uses hashing and does not maintain sorted keys.

Real-life: product code → price.

Where & How STL Containers Are Used

  • vector: marks, records and indexed collections.
  • list: collections with insertion and deletion requirements.
  • stack: undo operations and LIFO workflows.
  • queue: scheduling and FIFO processing.
  • map: dictionaries and sorted lookup tables.
  • unordered_map: hash-based lookup and frequency counting.

Overall Visual: Choosing the Right Container

Dynamic sequence→vector / list→LIFO→stack→FIFO→queue→Key-value→map / unordered_map

The correct STL container depends on how data must be stored, accessed, inserted, removed and searched.

Quick Summary

Vector
Dynamic indexed sequence.
Stack & Queue
LIFO and FIFO processing.
Map
Ordered key-value storage.
Unordered Map
Hash-based key-value lookup.

Common Errors

  • Forgetting the required STL header.
  • Accessing top() or front() on an empty adaptor.
  • Assuming vector and list have identical access behavior.
  • Dereferencing an invalid iterator.
  • Confusing map and unordered_map ordering.
  • Not checking whether a searched key exists.

Viva Questions

An STL container is a standard library data structure used to store and organize collections of objects.
A vector is a dynamic sequence container that provides indexed access.
A list is a linked sequence container useful for insertion and deletion operations.
A stack follows LIFO — Last In, First Out.
A queue follows FIFO — First In, First Out.
A map stores unique key-value pairs in sorted key order.
unordered_map stores key-value pairs using hashing without sorted key order.
It adds an element at the end of a compatible sequence container.
It removes the top element of a stack or the front element of a queue.
It searches for a key and returns an iterator to the matching element or end().
They provide tested, reusable data structures and standard interfaces.
Each STL component is declared by its corresponding standard header.

CONCEPT

Understanding Destructors

What is a Destructor?

A destructor is a special member function of a class that is automatically called when an object is destroyed.

Its main purpose is to perform cleanup work, such as releasing dynamically allocated memory or other resources owned by the object.

A destructor has the same name as the class preceded by a tilde (~) and it does not have a return type.

Real-Life Example

Consider a temporary room booking in a hotel system. When the booking is created, resources are assigned to it. When the booking ends, those resources can be released.

A destructor performs a similar cleanup role when an object reaches the end of its lifetime.

Where & How Is It Used?

  • Dynamic Memory: Release memory allocated using new.
  • File Handling: Close resources owned by an object when appropriate.
  • Database / Network Objects: Perform object-level cleanup when resources are no longer needed.
  • Game Development: Clean up resources associated with temporary game objects.
  • Resource Management: Keep object ownership and cleanup organized.

Characteristics of a Destructor

01

Same Class Name

The destructor uses the class name preceded by the tilde symbol (~).

02

No Return Type

A destructor does not have a return type, including void.

03

No Parameters

A destructor does not accept parameters.

04

Called Automatically

It is automatically invoked when an object is destroyed.

05

One Destructor

A class can have only one destructor and it cannot be overloaded.

06

Cleanup Role

It can release resources owned by the object, such as dynamically allocated memory.

SYNTAX

Basic Destructor Syntax

class ClassName
{
public:

    ~ClassName()
    {
        // cleanup code
    }
};

When Is a Destructor Called?

For a local object, the destructor is automatically called when the object goes out of scope. For an object created dynamically using new, the destructor is invoked when the object is destroyed using delete. 

Demo obj;

// Destructor is called automatically
// when obj goes out of scope.
Demo *ptr = new Demo();

delete ptr;

// Destructor is invoked as part of
// destroying the dynamically allocated object.

Constructor vs Destructor

Constructor

  • Called when an object is created.
  • Used mainly for initialization.
  • Has the class name.
  • Can be overloaded.
  • Can accept parameters.

Destructor

  • Called when an object is destroyed.
  • Used mainly for cleanup.
  • Has ~ followed by the class name.
  • Cannot be overloaded.
  • Does not accept parameters.

PROBLEM 01

Basic Destructor

Problem Statement

Write a C++ program to create a class Student with a constructor and destructor. Display messages to demonstrate when the constructor and destructor are called.

Theory / Concept

A destructor is automatically called when the object is destroyed. In this program, the constructor shows object creation and the destructor shows object cleanup.

SYNTAX

Destructor Syntax

~ClassName()
{
    // cleanup code
}

For the Student class: 

~Student()
{
    cout << "Destructor Called";
}

Algorithm

  1. Start the program.
  2. Define the Student class.
  3. Define a constructor that displays a message.
  4. Define a destructor that displays a message.
  5. Create a Student object.
  6. Display a message while the object is being used.
  7. Allow the object to go out of scope.
  8. Observe the destructor message.
  9. Stop the program.

C++ Program

#include <iostream>

using namespace std;

class Student
{
public:

    Student()
    {
        cout << "Constructor Called" << endl;
    }

    ~Student()
    {
        cout << "Destructor Called" << endl;
    }

    void display()
    {
        cout << "Student Object is in Use" << endl;
    }
};

int main()
{
    Student s;

    s.display();

    return 0;
}

Expected Output

Constructor Called
Student Object is in Use
Destructor Called
VISUAL EXPLANATION

Basic Destructor Flow

Student s Object created
→
Constructor Initialization
→
Destructor Cleanup when object is destroyed

Program Explanation

  • The object s is created inside main().
  • The constructor is called automatically during object creation.
  • The display() function uses the object.
  • When main() ends, the local object is destroyed.
  • The destructor is then called automatically.

Real-Life Connection

A temporary software object may acquire resources during its lifetime. When that object is no longer needed, cleanup can be performed automatically as the object is destroyed.

Key Points

  • A destructor starts with the tilde (~).
  • It has the same name as the class.
  • It has no return type.
  • It takes no parameters.
  • It is called automatically when the object is destroyed.

Common Errors

Missing Tilde

The destructor must use ~ before the class name.

Return Type

A destructor must not have a return type.

Wrong Name

The destructor name must match the class name.

Parameters

A destructor does not accept parameters.

PROBLEM 02

Destructor with Multiple Objects

Problem Statement

Write a C++ program to create three objects of a class and demonstrate the order in which their constructors and destructors are called.

Theory / Concept

When multiple local objects are created in the same scope, their destructors are called in the reverse order of their construction. This follows a Last In, First Out (LIFO) pattern.

SYNTAX

Destructor with Multiple Objects

class ClassName
{
public:

    ClassName()
    {
        // constructor
    }

    ~ClassName()
    {
        // destructor
    }
};

ClassName obj1;
ClassName obj2;
ClassName obj3;

Algorithm

  1. Start the program.
  2. Define a class with a constructor and destructor.
  3. Create three objects in sequence.
  4. Display a message from the constructor.
  5. Display a message from the destructor.
  6. Observe constructor execution order.
  7. Observe destructor execution order.
  8. Stop the program.

C++ Program

#include <iostream>

using namespace std;

class Demo
{
    int id;

public:

    Demo(int n)
    {
        id = n;
        cout << "Constructor: Object " << id << endl;
    }

    ~Demo()
    {
        cout << "Destructor: Object " << id << endl;
    }
};

int main()
{
    Demo obj1(1);
    Demo obj2(2);
    Demo obj3(3);

    cout << "All objects are in use." << endl;

    return 0;
}

Expected Output

Constructor: Object 1
Constructor: Object 2
Constructor: Object 3
All objects are in use.
Destructor: Object 3
Destructor: Object 2
Destructor: Object 1
VISUAL EXPLANATION

Construction vs Destruction Order

Object 1 Created first
Destroyed last
Object 2 Created second
Destroyed second
Object 3 Created last
Destroyed first 
Creation:     1 → 2 → 3
Destruction:  3 → 2 → 1

Program Explanation

  • Object 1 is created first.
  • Object 2 is created second.
  • Object 3 is created last.
  • The constructors execute in the order 1 → 2 → 3.
  • The destructors execute in reverse order 3 → 2 → 1.
  • This demonstrates the LIFO order of destruction for these local objects.

Real-Life Connection

Think of objects like books placed one above another. The last book placed on the stack is the first one removed. Local object destruction follows a similar reverse-order pattern.

Key Points

  • Objects are constructed in creation order.
  • Local objects are destroyed in reverse construction order.
  • The last-created object is destroyed first.
  • This is commonly described as LIFO order.

Common Errors

Wrong Order

Do not assume destructors run in the same order as constructors.

Scope Confusion

Object lifetime depends on its storage duration and scope.

Missing Destructor

Ensure the destructor is declared inside the class.

Wrong Object ID

Initialize and display the correct object identifier.

PROBLEM 03

Destructor with Dynamic Memory

Problem Statement

Write a C++ program to dynamically allocate memory for an integer using new and release the memory using delete through a destructor.

Theory / Concept

Dynamically allocated memory remains allocated until it is explicitly released. A destructor can be used to release resources owned by an object. In this example, the object owns an integer allocated with new, and the destructor releases it using delete.

SYNTAX

Destructor with Dynamic Memory

class ClassName
{
    data_type *ptr;

public:

    ClassName()
    {
        ptr = new data_type;
    }

    ~ClassName()
    {
        delete ptr;
    }
};

Dynamic Object Creation:

ClassName *obj = new ClassName();

delete obj;

Algorithm

  1. Start the program.
  2. Define the Demo class.
  3. Declare an integer pointer.
  4. Allocate memory using new inside the constructor.
  5. Assign a value to the allocated memory.
  6. Display the value.
  7. Define a destructor.
  8. Release the allocated memory using delete.
  9. Destroy the dynamically allocated object.
  10. Stop the program.

C++ Program

#include <iostream>

using namespace std;

class Demo
{
    int *ptr;

public:

    Demo()
    {
        ptr = new int;
        *ptr = 100;

        cout << "Memory Allocated" << endl;
    }

    void display()
    {
        cout << "Value: " << *ptr << endl;
    }

    ~Demo()
    {
        delete ptr;

        cout << "Memory Released" << endl;
    }
};

int main()
{
    Demo *obj = new Demo();

    obj->display();

    delete obj;

    return 0;
}

Expected Output

Memory Allocated
Value: 100
Memory Released
VISUAL EXPLANATION

Dynamic Memory Cleanup

new Demo() Object created dynamically
→
new int Memory allocated for integer
→
delete obj Destructor runs and releases memory

Program Explanation

  • The pointer ptr stores the address of dynamically allocated memory.
  • The constructor allocates memory using new.
  • The value 100 is stored in the allocated memory.
  • The object is created dynamically using new Demo().
  • delete obj destroys the object and invokes its destructor.
  • The destructor releases the integer memory using delete ptr.

Real-Life Connection

Software objects may temporarily own memory or other resources. When ownership ends, those resources should be released so that the application does not keep unnecessary resources allocated.

Key Points

  • Use new to dynamically allocate memory.
  • Use delete to release a single dynamically allocated object or value.
  • A destructor is a natural place for object-owned cleanup.
  • Cleanup should match the allocation strategy.

Common Errors

Memory Leak

Forgetting to release dynamically allocated memory can cause a memory leak.

Wrong Delete

Match delete with memory allocated by new.

Null / Invalid Pointer

Do not dereference an invalid or uninitialized pointer.

Double Delete

Do not release the same dynamically allocated memory twice.

PROBLEM 04

Complete Object Lifecycle

Problem Statement

Write a C++ program to demonstrate the complete lifecycle of an object using a constructor, member function and destructor.

Theory / Concept

An object has a lifetime that begins when it is constructed and ends when it is destroyed. The constructor prepares the object, member functions operate on it, and the destructor performs final cleanup when its lifetime ends.

SYNTAX

Constructor + Destructor

class ClassName
{
public:

    ClassName()
    {
        // initialization
    }

    void display()
    {
        // object operation
    }

    ~ClassName()
    {
        // cleanup
    }
};

Algorithm

  1. Start the program.
  2. Define the Employee class.
  3. Declare employee data members.
  4. Define a constructor to initialize the object.
  5. Define a member function to display the object details.
  6. Define a destructor to display the cleanup message.
  7. Create an Employee object.
  8. Use the object to display its details.
  9. Allow the object to go out of scope.
  10. Observe the destructor call.
  11. Stop the program.

C++ Program

#include <iostream>
#include <string>

using namespace std;

class Employee
{
    int empId;
    string name;

public:

    Employee()
    {
        empId = 101;
        name = "Riya";

        cout << "1. Constructor Called" << endl;
    }

    void display()
    {
        cout << "2. Employee Details" << endl;
        cout << "ID: " << empId << endl;
        cout << "Name: " << name << endl;
    }

    ~Employee()
    {
        cout << "3. Destructor Called" << endl;
    }
};

int main()
{
    Employee e;

    e.display();

    cout << "4. End of main scope" << endl;

    return 0;
}

Expected Output

1. Constructor Called
2. Employee Details
ID: 101
Name: Riya
4. End of main scope
3. Destructor Called
VISUAL EXPLANATION

Object Lifecycle

Create Employee e;
→
Constructor Initialize object
→
Use Object e.display()
→
Scope Ends main() ends
→
Destructor Final cleanup

Program Explanation

  • Creating Employee e invokes the constructor automatically.
  • The constructor initializes employee ID and name.
  • The display() function accesses the initialized object.
  • When the object reaches the end of its lifetime, the destructor is invoked automatically.
  • This demonstrates the complete sequence: construction → use → destruction.

Real-Life Connection

An employee record object may be created, used to perform operations, and eventually removed from memory when its lifetime ends. The constructor and destructor provide clear points for initialization and cleanup.

Key Points

  • Object lifetime starts with construction.
  • Member functions operate while the object exists.
  • Object destruction occurs at the end of its lifetime.
  • The destructor performs final object-level cleanup.
  • Understanding object lifetime helps explain resource management.

Common Errors

Wrong Sequence

Remember that construction occurs before normal object use.

Destructor Name

Use ~ followed by the exact class name.

Return Type

Neither constructors nor destructors use a return type.

Scope

Understand when the object leaves its scope and is destroyed.

P21

Interactive Graphics Application

Combine computer graphics concepts into a complete interactive application with drawing, transformation, animation and visual feedback.

Mini Project Canvas Interaction Animation
01

Project Aim & Objectives

Aim: To design and implement an interactive computer graphics application by combining the concepts studied throughout the practical series.

  • Combine geometric primitives and coordinate systems.
  • Apply 2D transformations such as translation, scaling, rotation, reflection and shearing.
  • Use clipping, curves or other graphics algorithms where appropriate.
  • Implement user interaction through mouse, pointer or keyboard events.
  • Create animation using a continuous rendering loop.
  • Organize graphics into reusable objects and application states.
  • Present a complete, usable graphics application rather than an isolated algorithm.
02

Project Concept

A graphics application is built by combining several smaller graphics operations. The final application should accept user input, update a graphical model and render the new state immediately.

1

Input

Mouse, pointer, keyboard or UI controls.

2

Model

Store shapes, coordinates, colors and transformations.

3

Algorithm

Apply drawing or graphics operations to the model.

4

Render

Convert the current state into visible graphics.

5

Feedback

Show the result and allow another interaction.

03

Foundation Concepts Used

Coordinates

Every graphical object needs a coordinate representation. A consistent coordinate system makes movement, selection and transformation easier.

Primitives

Lines, circles, rectangles, polygons and paths form the basic visual components of the application.

Transformations

Translation, scaling and rotation allow the same object to be repositioned, resized and oriented dynamically.

Interaction

Events connect the user's actions to changes in the graphics model.

Animation

A render loop repeatedly updates the model and redraws the scene to create motion.

Visualization

The application should make the effect of graphics operations immediately visible to the user.

08

Minimum Project Features

Required

  • At least three graphical object types.
  • At least two transformation operations.
  • At least one direct user interaction.
  • Clear visual feedback.
  • Reset or clear functionality.

Recommended

  • Undo / redo.
  • Object selection and movement.
  • Animation.
  • Keyboard shortcuts.
  • Data or scene export.

Advanced

  • Clipping.
  • Bezier or B-Spline paths.
  • Collision detection.
  • Layer management.
  • Three.js 3D extension.
09

Project Development Steps

  1. Define the problem: Decide what the application should allow the user to create or control.
  2. Design the scene: Identify objects, coordinates, controls and states.
  3. Implement primitives: Draw the basic shapes first.
  4. Add transformations: Implement movement, scaling and rotation.
  5. Add interaction: Connect pointer or keyboard events to the graphics model.
  6. Add animation: Update changing properties inside a render loop.
  7. Test: Check boundary conditions, unusual inputs and repeated interactions.
  8. Polish: Improve controls, labels, feedback and usability.
10

Experiments & Evaluation

Experiments

  1. Create a shape editor with translation, scaling and rotation.
  2. Add a second object and implement independent transformations.
  3. Implement an animation mode using requestAnimationFrame().
  4. Add keyboard controls for moving the selected object.
  5. Add an undo operation by storing previous application states.
  6. Extend the project with a curve, clipping algorithm or collision detection.

Evaluation Checklist

  • Does the application respond correctly to user input?
  • Are transformations mathematically correct?
  • Are objects rendered consistently after every update?
  • Does animation remain stable during interaction?
  • Is the interface understandable without explaining every control?
  • Can the student explain the graphics concepts used in the implementation?
11

Common Mistakes

  • Writing all drawing logic directly inside event handlers instead of maintaining a graphics state.
  • Changing an object but forgetting to redraw the scene.
  • Using inconsistent coordinate systems between the interface and Canvas.
  • Applying transformations in an unintended order.
  • Creating multiple animation loops for the same scene.
  • Not validating object positions at the Canvas boundaries.
  • Making the project visually complex without having a clear underlying graphics model.
12

Viva Questions

What is the difference between a graphics algorithm and a graphics application?

A graphics algorithm performs a specific computational operation, while an application combines algorithms, data, interaction and rendering to solve a complete user problem.

Why should graphical objects be stored as data?

Storing object data makes selection, transformation, undo, animation and repeated rendering possible without losing the application's state.

What is the graphics rendering loop?

It is the repeated process of updating application state and drawing the current scene, commonly synchronized with the browser using requestAnimationFrame().

Why does transformation order matter?

Matrix multiplication is generally not commutative, so applying the same transformations in a different order can produce a different result.

How can user interaction be added to a graphics application?

Input events such as pointer, mouse and keyboard events can update the graphics state, followed by a redraw.

How can this project be extended to 3D?

The application can move from a 2D Canvas model to a 3D scene using concepts such as 3D coordinates, cameras, lights, materials, textures and a WebGL-based renderer such as Three.js.
